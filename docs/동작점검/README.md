# 운영 점검 — 문서 구조와 규약

## 파일 종류

| 경로 | 누가 만드나 | 무엇인가 |
|---|---|---|
| `YYYY-MM-DD_마흐디_운영점검보고서.md` | **사람** | 그날의 해석 — 이상점 정리, fix 계획, 고도화 방안 |
| `auto/YYYY-MM-DD_지표.md` | `scripts/daily_ops_report.py` | 표와 전일 델타만. **해석 없음** |
| `auto/YYYY-MM-DD_지표.json` | 위와 동일 | 기계 판독용 — 다음날 델타 계산에 쓴다 |
| `hypotheses.yaml` | **사람(fix 구현 시점)** | 예측치 — 다음 거래일 리포트가 자동 대조 |

자동 산출은 `auto/`에만 두고 **사람 보고서가 그것을 인용한다.** 도구는 판정하지 않는다.

## 규약 — 예측치를 먼저 적는다

> **fix를 구현하는 세션은 그 자리에서 `hypotheses.yaml`에 예측치를 적는다.**
> 다음 거래일 리포트가 자동으로 대조해 §0에 낸다.
> **예측치를 못 적겠으면 그 fix는 아직 근거가 부족한 것이다.**

마지막 문장이 이 규약의 진짜 가치다. 2026-07-30 보고서는 위상 격자 스냅의 트레이드오프를
*"밀린 사이클의 데이터는 어느 쪽이든 이미 유실된 뒤다"* 라고 **추론으로 단정**했고, 07-31 실측에서
그게 틀렸음이 드러났다(밀림 83→46건인데 결손은 25→47분). 그 추론이 예측치 형태로 강제됐다면
그날 바로 걸렀을 것이다.

### 그리고: 예측은 "좋아진다"가 아니라 **"존재한다"** 에서 시작한다

> **fix가 어떤 값을 "쓰는" 경우, 그 값이 실제로 생산되고 있다는 것을 먼저 예측치로 적는다.**
> "X를 개선한다"의 예측치는 "X가 좋아진다"가 아니라 **"X가 존재한다"** 부터다.

2026-08-03에 이 규약의 빈틈이 드러났다. 그날 예측 13개 중 12개가 자동 대조로 즉시 확인됐지만,
**그 어떤 가설도 §2-1의 버그를 잡지 못했을 것이다** — 아무도 "감마플립이 계산되는가"를 예측치로
적지 않았기 때문이다. 그것이 *당연히 되고 있다*고 가정했다. 실제로는 `find_gamma_flip()`이
전 이력에서 **한 번도 값을 돌려준 적이 없었고**(`iv=0` 레그 하나가 41개 그리드 전체를 NaN으로
오염시켰다), 그 결과 앙상블 멤버 `options_flow`가 넉 달간 영구 미가용이었다. 넉 달 동안 GEX·
감마플립을 "개선"해 온 대상이 애초에 존재하지 않았던 것이다.

그래서 §5-1의 **신호 도달률** 지표(`db.signal_reach`, 자동 리포트 §14)가 생겼다 — 커버리지가
*"데이터가 DB에 있는가"* 를 재는 자리 바로 아래에서 *"그 데이터가 판단까지 갔는가"* 를 잰다.

### 그리고: 예측 지표에는 **역할**이 있다 (2026-08-05 고도화#2 / 규약 E)

> **모든 가설은 `역할: 주장` 지표를 하나 이상 가져야 한다** — 그 가설이 *실제로 주장하는 것*을
> 재는 지표다. 없으면 자동 리포트 §0이 **「판정 불가」** 로 낸다.
> **트레이드오프가 있으면 `대가:` 문구로 선언하고 `역할: 대가` 지표를 함께 등록한다.**

2026-08-04 `p4`가 이 규약을 만들었다. 그 가설은 *"ATM 히스테리시스로 롤링 왕복이 사라진다"* 고
주장하면서 등록 지표가 `chain_age_seconds_max`와 `log_volume.human_lines`였다 — **둘 다 왕복을
재지 않는다.** 08-05 실측에서 왕복률은 36.1% → 47.5%로 **나빠졌는데도** §0은 "확인"을 냈다.
**자기 주장을 검정하지 않는 지표로 받은 합격이다.**

같은 날 `p3`(사이클 예산)는 반대쪽 구멍을 보여줬다. 가설 문구가 *"(대가로 얇은 사이클이
생긴다)"* 라고 **대가를 선언해 놓고 그것을 재는 지표를 등록하지 않았다.** 그 결과 밀림 0건이라는
훌륭한 숫자 뒤에서 먼슬리 북이 38% 확률로 얇아지고 4분이 통째로 사라진 것을 **다음날에야** 알았다.

주장 지표는 *얻은 것*, 대가 지표는 *잃은 것*이다. 규약 A~D가 "같은 것을 두 번 쓰지 마라"의
변주라면 **E는 "한쪽만 재지 마라"** 다. `tests/test_ops_hypotheses.py`가 이 저장소의 `pending`
항목 전부에 대해 기계적으로 강제한다.

### 그리고: 주장 지표는 **주장과 같은 축**으로 잘려야 한다 (2026-08-06 Fix#5 / 규약 F)

> **원인을 주장하는 fix는 원인별 지표로 검정한다.** 총 건수만 세는 지표로는 원인에 관한 주장을
> 확인할 수도 반증할 수도 없다.

2026-08-06에 규약 E의 다음 빈틈이 드러났다. `2026-08-05-p2`는 *"**read 타임아웃**을 엔드포인트별로
나누면 실패가 사라진다"* 고 주장하면서 등록 지표가 `failures.만기 유동성 폴링 실패`(총 건수)였다.
실측 7건 → 자동 판정 **반증**. 그런데 그 7건은 **전부 EGW00201(레이트리밋)이었고 ReadTimeout
기인은 0건**이었다 — **그 가설의 주장은 오히려 맞았다.**

규약 E가 "얻은 것과 잃은 것을 같이 재라"였다면, **F는 "재는 축이 주장하는 축과 같아야 한다"** 다.
그래서 `failures_by_cause`(§11 실패 표의 원인 열)가 생겼다.

### 그리고: 경로가 **존재하는지** 먼저 검사한다 (2026-08-06 Fix#3)

> 지표 경로 오타는 「실측 없음」과 구별되지 않아 **가설을 조용히 무력화한다.**
> 자동 리포트 §0이 그것을 **「경로 없음」** 배너로 따로 낸다 — 표 안의 한 줄이면 묻힌다.

2026-08-05 예측 13건 중 **6건이 주장 지표를 하나도 못 받았다**. `db.decisions.…`,
`db.tables.<이름>.rows`, `db.member_availability.<멤버>.…` — 사람이 자연스럽게 적은 경로가
리포트 구조에 없었다. 그래서 `p1`의 **대가 지표가 12배 초과**(ENTER 예측 5건 이하에 실측 62건)한
것을 아무도 자동으로 알아채지 못했다.

두 방향으로 고쳤다. **경로를 사람에게 맞추고**(위 세 경로가 이제 전부 값을 낸다),
`tests/test_ops_hypotheses.py`가 **`db.`을 포함한** 모든 경로의 첫 마디를 검사한다
(08-06 아침 커밋이 만든 테스트는 `db.`를 명시적으로 면제했고, 그날 죽어 있던 경로 12개는
전부 `db.`로 시작했다).

**소급 적용하지 않는다.** 검증예정일이 지난 항목에 예측을 새로 붙이는 것은 *숫자를 보고 예측을
고치는 것*이라 규약의 뿌리를 무너뜨린다 — 그런 항목은 `inconclusive`로 닫고 이유를 적는다
(`2026-08-04-p4`가 그 예다).

`hypotheses.yaml`의 `상태`는 **자동으로 바뀌지 않는다** — 사람이 보고서를 쓰면서 손으로 확정한다.
자동 판정이 틀렸을 때 조용히 덮이는 것을 막기 위함이다.

## 자동 집계 실행

장마감 자동 종료(`scripts/stop_mahdi_marketclose.bat`)가 taskkill 이후 한 줄로 호출한다 —
그 시점에 관측 루프는 이미 종료돼 로그가 완결돼 있고, DB/Redis는 의도적으로 계속 실행 중이다.

수동 실행(과거 날짜 재집계, 로그가 남아 있는 한):

```
uv run python scripts/daily_ops_report.py [--date YYYY-MM-DD] [--no-db] [--out-dir DIR]
```

`--no-db`는 Docker가 꺼진 상태에서 로그 집계만 뽑을 때 쓴다.

## 지표를 늘릴 때

로직은 `mahdi/ops/`에 두고 `scripts/`는 얇게 유지한다(`scripts/log_marketclose_stop.py`가
같은 규약을 문서로 남기고 있다 — 실제 로직은 pytest로 테스트되는 파이썬 쪽에).

- `log_metrics.py` — 순수 파서(로그 라인 → dict). 파일 I/O 없음.
- `db_metrics.py` — SQL 집계. **COCKPIT 배지와 계산 함수를 공유한다**(리포트와 배지가 다른 답을
  내면 어느 쪽을 믿을지 알 수 없다).
- `report.py` — 순수 렌더러(dict → 마크다운).
- `hypotheses.py` — 가설 로드 + 대조.

새 지표는 `tests/fixtures/observation_loop_sample.log`에 대표 줄을 추가하고
`tests/test_ops_log_metrics.py`에서 손계산 값과 대조한다.
