## 작성 시 규칙

- **인용 없는 이상점은 쓰지 않는다.** 로그 시각·건수·파일명이 반드시 붙는다.
- **"개선한다"류 동사를 쓰지 않는다.** 어느 파일 어느 함수에서 무엇을 어떻게 바꾸는지 쓴다.
- **추론과 실측을 섞지 않는다.** 2026-07-30이 추론을 단정으로 쓰고 다음날 틀렸다 —
  그래서 예측치 규약이 생겼다. 추론이면 "추론"이라고 쓰고 예측치로 바꿔 검정 대상으로 만든다.
- **판정 보류를 부끄러워하지 않는다.** 틀린 확정보다 정직한 보류가 낫다.
  단, 무엇을 보면 판정되는지는 반드시 쓴다.
- **초안이 틀렸으면 지우지 말고 정정 표로 남긴다.** 2026-08-12 §4 상단이 그 예다 —
  구현하다 초안 세 곳이 틀린 것을 발견하고 「초안이 적은 것 / 실제」 표로 남겼다.
- **전일 보고서와의 델타**를 쓴다. 절대값보다 변화가 정보량이 크다.
- 장중 점검이면 **fix는 계획만** 세운다. 적용은 장후로 미룬다.
