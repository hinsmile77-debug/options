## §4. HMM 재학습 — 결함 넷

상세 근거는 `docs/dev_memory/DECISION_LOG.md` 2026-08-10, 격리 기록은
`data/models_quarantine/README.md`(gitignore라 이 저장소엔 안 올라간다).

### 4-1. `startprob_` one-hot 붕괴 (R1 + R3)

첫 산출물이 라이브에서 **전 이력 8,241분을 단일 상태**로 판정했다.

    startprob_ = [0, 0, 0, 0, 0, 1.0, 0, 0]   # 7개가 부동소수 정확히 0.0

- **R1** `fit()`이 `lengths=` 없이 25세션을 한 시퀀스로 학습 → startprob 표본이 1개 → 붕괴.
- **R3** `step()`이 **길이 1**을 넘김 → 길이 1의 사후확률은 `normalize(startprob ⊙ emission)`이라
  **전이행렬이 통째로 안 쓰임** → startprob이 답을 지배.

`predict()`의 docstring은 처음부터 *"최근 윈도우 (n,6)"* 를 받도록 적혀 있었고 내부도 전방
필터링이다 — **설계는 맞았고 호출부가 계약을 어겼다.**

### 4-2. 가드 둘이 둘 다 다른 것을 재고 있었다 (R4)

- **방문 상태 검사**: 배치 Viterbi로 "8/8 방문" → 라이브 축으로 재면 **1/8**. 규약 F의 코드판.
- **수렴 가드**(`monitor_.converged`): hmmlearn 0.3.3 구현상 `iter == n_iter`(비수렴)와
  **음수 delta**(발산)에서 정확히 True. 그날 발산 후보 둘이 restart **패자**였기에 저장물이
  우연히 멀쩡했다.

재구축한 3겹이 각자 무엇을 지키는지 **음성 대조로 확인**했다 — 붕괴 모델은 `check_startprob`이
잡고, R3 회귀(`window=1`)는 `check_live_diversity`가 잡는다. **어느 하나로 다른 쪽을 대신할 수
없다.**

### 4-3. ATM IV가 폴링 격자를 타고 있었다 (R6) — **가장 깊다**

R1·R3 수정 후 재학습본은 게이트 3겹을 **전부 통과**했다. 그런데 `RegimeStateMachine`에 직접 태워
08-10을 재생하니 **분당 99.2%가 레짐 전이**였고 `stability_flag`는 한 번도 안 걸렸다 — 모델이
매분 **확률 1.000으로 확신하며** 뒤집혔기 때문이다.

원인은 피처였다. `_update_atm_iv()`가 **모든 북의 IV를 평균**하는데 위클리는 격분에만 조회된다:

| | 북 구성 | 평균 IV |
|---|---|---|
| 짝수분 | 위클리(08-10) + 먼슬리(08-13) | 0.5285 |
| 홀수분 | 먼슬리 단독 | 0.7387 |

`iv_chg` 차분 lag1 자기상관 **−0.900**(완벽한 구형파). HMM이
**"짝수분=TREND_UP_STRONG / 홀수분=VOL_COMPRESSION"을 94% 일치**로 재현했다.
**레짐이 시장이 아니라 폴링 격자를 따라갔다.**

`_books_due_this_cycle()` docstring은 이미 *"먼슬리를 먼저 조회해 ATM IV가 항상 주력 북 기준으로
잡히도록"* 이라고 적고 있었다 — **의도는 맞았고 구현이 안 지켰다.** 2026-08-06 Fix#4가 체인 나이
지표에서 고친 것과 **같은 계열**이고 이 함수만 빠져 있었다.

### 4-4. `fit()`이 발산한 후보를 승자로 뽑았다 (R7)

재계산 피처로 학습하니 승자가 **delta=−0.32로 발산한 후보**였다(점수만 보고 골랐다).

> §1~§8은 15:11 실측 위에서 쓰였다. 종일(494분)로 다시 보니 **15:11~15:45의 34분에 오늘의
> 실질적 사건이 전부 몰려 있었고**, 그것을 재는 계측 둘이 동시에 틀렸다.

## §9-1. 파서가 재시도 사이클을 못 읽는다 (신규 · 10일 잠복)

`main.py` 포맷과 `log_metrics.py` 정규식이 **`재시도함`의 위치가 다르다.**

```
포맷 (main.py:283)          "(rows=%d, 밀림=%.1f초%s, 타폴러동시호출추정=%s) 분=%s"
                                            └─ 재시도함이 밀림 뒤
정규식 (log_metrics.py:46)  \(rows=(\d+)(?:, 재시도함)?, 밀림=([\d.-]+)초, 타폴러…
                                     └─ rows 뒤로 기대
```

포맷은 07-28(`e85e65d`), 정규식은 08-01(`6f15e84`) — **정규식이 태어날 때부터 틀렸다.**
10일 잠복 후 08-10 15:15에 첫 발현했다.

**재시도는 상황이 나쁠 때만 일어난다** — 파서는 정확히 가장 나쁜 사이클에서만 눈이 멀었다.

## §9-3. 15:15 옵션체인 한 분 전멸 (진짜 사건)

**원인이 다른데 지표가 하나라 같은 칸에서 만났다**(규약 F가 지적하는 형태의 지표 쪽 재현).

## §9-8. 후속 3종 구현 (저녁 3차)

§9-7에 미수정으로 남긴 셋을 구현했다. **구현하면서 검증한 두 가지가 앞 절의 서술을 정정한다.**

### (1) 0행 분을 원인별로 가른다

`db.chain_minute_coverage.zero_row_by_cause` 신설 — 로그 축(`cycles.zero_row_minutes` /
`minutes_with_cycle`)과 DB 축을 합쳐 세 원인으로 나눈다:

| 원인 | 08-10 | 무엇인가 |
|---|---|---|
| **수집 전멸** | **1분 (15:15)** | 사이클은 돌았는데 적재 0행 |
| 사이클 없음 | 0분 | 그 분에 사이클 자체가 없었다 |
| 이웃 분 적재 | 0분 | 사이클도 행도 있었는데 라벨이 옆 분으로 갔다 |

이제 `2026-08-07-fix3`(분 경계 스냅)의 불변식 반증이 **그 fix와 무관한 사건**이었음이 지표로
보인다. 08-07 이전 로그처럼 `분=` 라벨이 없으면 `labelled: false`를 함께 내 정확도가 낮다는
사실을 남긴다.

### (2) §14에 「GEX 입력이 없던 분」 — 그리고 **§9-3의 서술 정정**

불변식 지표(`signal_decisions.chain_leg_count`가 0/NULL인 분)를 신설했다.
**08-10 실측은 0분이다.** 15:15에 체인 적재가 0행이었는데도 판단은 눈이 안 멀었다:

```
signal_decisions 15:15 → chain_leg_count=10, gex non-null, gex_expiry 2026-08-13
```

`db.option_chain_as_of()`의 **신선도 창**이 직전 분 스냅샷을 실어 줬기 때문이다.

따라서 §9-3이 인용한 로그 문구 *"이 분은 GEX/감마플립 입력이 없다"* 는 **과장이었다.**
그 줄은 폴링 루프에서 나오므로 **그 분의 적재**만 알고 판단이 무엇을 봤는지는 모른다 —
자기가 아는 것보다 넓게 말하고 있었다. `LOG_CHAIN_CYCLE_EMPTY` 문구를 정정했다:

> 이 분의 체인은 비었다 — 판단은 신선도 창 안의 직전 스냅샷을 쓴다(§14 GEX 입력 없던 분에서 확인)

**전멸이 무해했다는 뜻은 아니다.** 신선도 창이 흡수할 수 있는 것은 짧은 결손뿐이고, 그 창이
얼마나 버티는지는 별개 문제다. 다만 **"판단이 눈이 멀었다"는 주장은 지표로 확인하기 전까지
하면 안 된다** — 그것이 이 지표를 만든 이유다.

### (3) §5에 북 수와 북당 호출 — 그리고 **§3-5의 사실 정정**

옵션체인 호출 수의 최대 구조 변수인 북 수를 값 옆에 인쇄하고, 전일과 다르면 경고한다.
규약 F는 **주장 역할**의 건수만 막고 대가는 의도적으로 면제하므로(그 판단은 그대로 둔다),
**읽는 사람이 나눗셈을 할 수 있게** 만드는 쪽을 택했다.

구현 중 확인한 실측이 §3-5를 정정한다:

| 날짜 | 북 수 | 옵션체인 REST |
|---|---|---|
| 08-06 | **3개** | 9,241 |
| 08-07 | **2개** | 7,388 |
| 08-10 | **2개** | 7,333 |

**북이 3→2로 준 것은 08-06 → 08-07이고, 08-10은 08-07과 같다.** §3-5는 그것을 "오늘 3→2"로
적었는데 틀렸다. 정정된 함의는 오히려 더 나쁘다 — `2026-08-07-e1`의 대가 지표 `<= 9,500`은
**fix가 실리기도 전에 이미 충족돼 있었다**(기준선을 3북 시절 값으로 잡았다).
