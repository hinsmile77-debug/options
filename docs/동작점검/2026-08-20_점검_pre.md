### [MW0601] 2026-08-20 장전 — Fix#9 첫 라이브 확인, 그리고 락을 만든 것은 수집기가 아니었다

- **증상**: 08:39 점검 세션의 `git status --porcelain`이 0바이트 `.git/index.lock`을 남겼다.
  08-18 16:20 · 08-19 12:41 · 08-20 08:39 — **사흘 연속, 전부 점검 세션의 git 호출 시각.**
- **확인**: 08:50:02 워치독이 `LOCK_SWEPT`로 열었다(0바이트 · 10.9분 방치 · git 프로세스 0개).
  같은 초에 `OK`가 이어져 판정 주기도 안 밀렸다. **`2026-08-19-fix9`의 첫 라이브 확인이다.**
- **원인**: `2026-08-19-fix10`이 **증거 수집기의** 락 생성만 없앴다. 락을 만드는 것은 수집기가
  아니라 **점검 세션이 직접 부르는 `git status`/`git diff`** 다. fix10은 옳게 확인되면서 원인을 못 덮는다.
- **결정**: 점검 경로의 git 호출을 `--no-optional-locks`(또는 `GIT_OPTIONAL_LOCKS=0`)로 고정한다.
  `STALE_LOCK_MIN_AGE_SECONDS`(600)는 **안 내린다** — *"모르는 채로 지우면 남의 작업을 깬다"*.
- **Why**: 락은 자동 회수되지만 **매 회차 10.9분씩 저장소가 잠긴다.** 워치독 문구가
  *"잦아지면 원인을 다시 볼 것"* 이라 적어 뒀고 사흘 연속이면 그 조건이다.
- **검증**: 다음 장전 회차에서 `git status` 직후 락이 안 생기는가. fix10의 주장 문구를
  「수집기가」 → 「**점검 경로 전체가**」로 넓혀 재등재.
