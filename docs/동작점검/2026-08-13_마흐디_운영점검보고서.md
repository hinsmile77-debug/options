## §7. 남은 질문

1. **장운영정보 수신 시각이 왜 DB에 없는가(§3-5).** 가르는 법 — 다음 기동 전에 DB에 직접 묻는다:
   `SELECT last_message_at, updated_at FROM market_halt_status WHERE id IS TRUE;`
   값이 있으면 §16 읽기 경로(계측 쪽), `NULL`이면 쓰기 쪽이다. 쓰기 쪽이면
   `MARKET_HALT_MESSAGE_TOUCH_SECONDS`의 초기값(`main.py:1264`)과 기준행 생성 시각을 본다.
   **이것이 갈리기 전에는 Fix#8을 착수하지 않는다.**

2. **`current` 0분은 북 수 때문인가, 오후 지연 때문인가(§3-2).**
   08-14가 가른다 — 북은 3개 그대로(regular 08-13이 만기 소멸하면 2개로 돌아갈 수도 있다.
   **그 경우 이 질문은 그날 못 갈리고 08-18로 밀린다**). 북 수와 `current`가 함께 움직이는지를 본다.

3. **`2026-08-12-g1`의 부등식을 어떻게 다시 쓸 것인가(§6).** `ws_disconnect.count >= 0`은
   검정력이 0이다. 다만 정상 재연결 분포의 표본이 08-04 1회 / 08-11 1회 / 08-12 31회 / 08-13 0회로
   **넷뿐이다** — 지금 임계를 정하면 그 임계가 곧 결론이 된다. 며칠 더 쌓은 뒤 정한다.

4. **`.watchdog_state.json`의 날짜 롤오버(장전 §1-1, 이틀째 미확인).**
   `{"date": "2026-08-12", "restarts": 1}`이 그대로다. **재기동이 한 번 나야만 갈린다** —
   재기동을 기다리는 것은 관측 전략이 아니므로, 대신 `tests/`에서 날짜가 바뀐 상태 파일을 주고
   `restarts`가 0으로 리셋되는지 단위 테스트로 답하는 것을 권고한다.

5. **오늘 「사람에게 도달한 경보 0건」이 경로 건강의 증거가 아니다(§3-4).**
   차단 사건이 없어 Slack/COCKPIT 도달 경로가 검정되지 않았다(규약 C). 도달 경로를 주기적으로
   자가 검정할 방법이 아직 없다.
