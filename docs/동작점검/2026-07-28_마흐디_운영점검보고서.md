## 5. 고도화 방안 (실행 점검 결과 기반)

1. **"재시작 직후 몇 사이클"을 라이브 검증의 결론 근거로 삼지 않는다** — 오늘 가장 중요한
   교훈이다. 아침에 "타폴러동시호출 0건으로 안정화"라고 결론 내린 근거가 재시작 직후 4사이클뿐이었고,
   실제로는 6시간 넘는 지속 운영에서 문제가 재발했다. 앞으로 fix의 라이브 검증은 최소 1~2시간
   연속 관측(또는 백오프 배율이 한 번 이상 상승-회복 사이클을 거치는 것을 확인) 후에 결론 내리는
   것을 표준 절차로 삼을 것을 제안한다.
2. **핵심 계측 지표의 일별 누적치를 COCKPIT에 노출** — 스케줄 밀림 건수, 타폴러동시호출추정
   분포, ZN 이중실패 여부 등은 지금 전부 로그를 grep해야만 확인 가능하다. 이 보고서 작성 자체가
   매번 로그 전수 분석에 크게 의존하고 있으므로, "오늘의 점검 요약" 배지 옆에 일별 누적 카운터
   패널을 하나 더 추가하면 향후 점검이 훨씬 가벼워진다.
3. **콜/풋 균형이 이제 안정적으로 1:1에 가까워졌으니 Phase 2 준비 착수를 검토할 시점** — 07-23
   1:1.8에서 오늘 1:0.97까지 4거래일 연속 개선 추세가 이어졌다. 데이터 품질 관점에서 더 이상
   "풋 데이터 부족"을 이유로 Phase 2(신호융합) 착수를 미룰 근거가 약해지고 있다 — 사용자와 착수
   시점을 논의해볼 만하다.
4. **스케줄 밀림 원인 분석의 "제외된 가설" 목록을 계속 갱신** — 07-24(동기 DB 쓰기), 07-27(같은
   가설 재반증), 07-28(공유 레이트리미터 접촉 확정 + 스태거링 부분적 효과 확인)까지 3거래일
   연속으로 가설을 좁혀왔다. 이번에도 DECISION_LOG에 "스태거링 단독으로는 지속 운영 중 재발 —
   재시작 직후에만 효과"를 명시적으로 기록해두는 게 다음 세션의 시간을 아껴준다.
