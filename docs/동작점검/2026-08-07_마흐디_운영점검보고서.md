## 4. 고도화 구현 결과 (5종, 전부 구현 완료)

### 고도화#1 — WS 구독을 ATM 창에서 분리한다 (`SubscriptionRetentionPool`)

창을 벗어난 구독을 **슬롯이 남는 동안 유지**하고, 슬롯이 필요하면 오래된 것부터 축출(LRU).

- **공짜에 가까운 근거**: WS 구독은 REST 페이서 예산을 1건도 안 쓰고, REST 폴링 대상은
  `desired_strikes`(창)에서 나오므로 유지 구독이 체인 수집을 1콜도 늘리지 않는다.
  08-07 실측 활성 슬롯 21~22/41.
- **구현 중 정정**: 예약 슬롯을 8 → **2**로 내렸다. 8이면 3북 날(설계 32/41)에 유지 가능
  슬롯이 1이 돼 이 고도화가 통째로 무력화된다. 롤 경로의 슬롯 부족은 예약이 아니라
  `ensure_free()`가 그때그때 축출해 해결한다.
- **롤 횟수는 안 줄어든다** — 이 고도화는 롤을 줄이는 게 아니라 롤의 대가를 없앤다.

### 고도화#4 — HMM 드라이런 실행 + **수렴 실패 시 저장 거부**

드라이런(7,682샘플)이 두 가지를 알려줬다:

- ✅ **잠재상태 방문 8/8개** — 08-03 드라이런의 경고("1~2개면 모델 구성을 의심")가 해소됐다.
- ⛔ **`Model is not converging` 다수** (로그우도 델타 음수). `fit()`은 예외를 안 던지므로
  **08-10에 그대로 저장했으면 수렴하지 않은 모델이 조용히 라이브에 올라갔을 것**이다.

→ `monitor_.converged`가 True가 아니면 **저장을 거부**하는 것을 기본값으로 했다.
