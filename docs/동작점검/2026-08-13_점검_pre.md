## 5. 신규 이상점 (P2 — 오늘 관측·거래에 위험 없음, 장후 처리)

### 5-1. [P2] 수집기 §8 가설 표의 「가설」 열이 전량 빈칸이다

**증상.** 오늘 08:31:36 생성된 `auto/2026-08-13_증거_pre.md` §8:

```
| `2026-08-11-eE-kis-latency-lever-deferred` | 2026-08-13 (도래) | pending | | | — |
| `2026-08-12-fix1-watchdog-restart-does-not-block-itself` | 2026-08-13 (도래) | pending | | | — |
```

12행 전부 「가설」 열이 비어 있고, 파이프가 하나 더 들어가 열이 밀렸다.

**근거.** `hypotheses.yaml`의 `가설:`은 전부 YAML 블록 스칼라(`|`)라 여러 줄이다.
수집기가 그것을 한 줄 셀로 접지 못하고, 접었더라도 본문의 `|`를 이스케이프하지 않는다.
(`2026-08-12-fix4`의 가설 본문에 실제로 `|`가 없지만 `전제레버` 열이 `—`로 밀린 것이 증거다 —
`2026-08-12-eE-on-congested-hours`만 `OPTION_CHAIN_SLOW_SERIES_CONGESTED_HOURS`가 제대로 찍혔다.)

**기준.** 이 표의 존재 이유는 「오늘 무엇을 판정하는가」를 한눈에 보는 것이다.
가설 문구가 없으면 id를 읽고 yaml을 다시 열어야 하고, 그러면 표가 없는 것과 같다.
`b9fa6c9`가 오늘 08:05에 커밋한 **새 도구의 첫 실전 결함**이다.

**영향.** 판정 자체에는 영향 없음(원본 yaml이 진실원천). 점검 세션의 왕복만 늘어난다.

**Fix 계획(장후 적용).** `docs/동작점검/tools/collect_evidence.py` 가설 표 생성부 —
`가설:` 블록의 첫 줄만 취해 60자로 자르고, `|`를 `\|`로 치환한 뒤 셀에 넣는다.
`전제레버` 열이 밀린 것은 그 이스케이프 누락의 결과이므로 같은 수정으로 함께 사라진다.

### 5-2. [P2] 추적 `.py`의 절반이 워킹트리 CRLF — `git diff`가 리뷰 도구로 무력화됐다

**증상.** 미커밋 111건인데 `mahdi/` + `scripts/` 범위(42파일)의 diff가
**17,770 insertions / 17,770 deletions**으로 정확히 대칭이다.

```
$ git diff --stat -- mahdi/main.py
 mahdi/main.py | 8282 +++++----  (4141 insertions(+), 4141 deletions(-))
$ git diff --ignore-all-space --stat -- 'mahdi/*' 'scripts/*'
(출력 없음)                      ← 실질 코드 변경 0
$ file mahdi/main.py
 ... with CRLF line terminators
$ git show HEAD:mahdi/main.py | file -
 ... (CRLF 없음)
```

추적 `.py` **156개 중 78개**가 워킹트리 CRLF이고, git blob은 LF다.
`.gitattributes` 없음, `core.autocrlf` 로컬·전역 모두 **미설정**.

**기준.** `dev_memory`에 CRLF 규약이 있지만 그것은 **`.bat` 한정**이다
(`DECISION_LOG.md:2292`「배치파일은 CRLF 줄바꿈 필수」, `CURRENT_STATE.md:635`).
`.py`의 줄바꿈은 어디에도 결정된 바 없다 — **신규 기록 대상**이다.

**영향.** (1) 장전 수집기 §1이 매일 「미커밋 111건」을 인쇄하는데 그 대부분이 내용 무변경이라
**진짜 미커밋 변경을 그 잡음이 가린다.** (2) 오늘처럼 「기동한 코드가 HEAD와 같은가」를 물을 때
`git status`가 답을 못 준다. 08-12에 「기동이 새 코드를 안 집었다」를 확인해야 했던 항목
(`NEXT_TODO.md:36-37`)이 정확히 이 질문이다.

**영향 없는 것.** 파이썬은 CRLF를 정상 처리하므로 **오늘 실행에는 아무 문제가 없다.**
`.bat` 규약도 그대로 지켜지고 있다.

**Fix 계획(장후 적용, 신중히).** 저장소 루트에 `.gitattributes`를 두고
`*.py text eol=lf` / `*.bat text eol=crlf` / `*.md text eol=lf`를 선언한 뒤
`git add --renormalize .` 를 한 번 돌린다.
⚠ **`.bat`의 CRLF는 절대 깨지면 안 된다**(2026-07-06에 cmd.exe 파싱이 깨진 전례).
renormalize 후 `scripts/*.bat`을 바이트 단위로 재확인하고, 장 마감 뒤 종료 배치가 정상
실행되는 것까지 본 다음 커밋한다. **개장일 아침에는 손대지 않는다.**
