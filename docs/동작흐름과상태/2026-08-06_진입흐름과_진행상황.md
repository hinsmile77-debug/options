### ⑤ 메타 라벨 — `classify()` (`mahdi/fusion/meta_label.py:44`)

```
score = regime_confidence × (동조수 / 가용멤버수)
      × 0.7   ← recent_slippage_elevated       (현재 항상 미적용: 체결 0건 = 사실)
      × 0.85  ← not gamma_regime_stable        (= GEX<0 또는 레짐 불안정)
      × 0.8   ← not foreign_flow_aligned       (외국인 수급 역행)
      × 0.5   ← event_proximity < 15분         (수기 캘린더 event_calendar.yaml)
      × (0.5 + 승률/2)  ← recent_same_setup_win_rate (현재 None = 중립 1.0배)
```

| 경계 | 값 | 결과 |
|---|---|---|
| `no_trade_max` | 0.15 | 미만 → **NO_TRADE** |
| `small_test_max` | 0.35 | 미만 → SMALL_TEST |
| `standard_max` | 0.65 | 미만 → STANDARD, 이상 → **HIGH_CONVICTION** |

> **08-05 Fix#3**: 종전엔 `MetaLabelContext()`를 **인자 없이** 생성해 곱셈 페널티 4종이 하나도 안 걸렸다. 특히 `gamma_regime_stable=True`가 낙관적 하드코딩이었다 — 08-05 HIGH_CONVICTION 6건의 확신도가 정확히 0.75(=1.0 × 3/4, 페널티 0회)였는데, GEX −9.9bn·`stability_flag=False`라면 0.75 × 0.85 = 0.6375 < 0.65 → **STANDARD로 내려갔어야 했다.** 2026-07-10 `warmup_fallback()` 하드코딩 인자 사고와 같은 형태의 결함.
> `recent_slippage_elevated=False`와 `recent_same_setup_win_rate=None`은 **추측이 아니라 사실**이라 그대로 둔다(`trade_history`/`execution_logs` 둘 다 0행).

### ⑥ 전략 팔레트 — `select_strategies()` (`mahdi/fusion/strategy_palette.py:52`)

NO_TRADE가 아니고 합의가 뚜렷할 때만 조회한다. v6 §11.4 **레짐 4행 × VRP 3열** 매트릭스:

| 레짐 행 | 저평가(vrp < −0.02) | 적정(±0.02) | 고평가(vrp > 0.02) |
|---|---|---|---|
| TREND_STRONG | `atm_long` | `itm_debit` | `debit_spread` |
| RANGE_TIGHT | `small_strangle_buy` | **`wait_and_see`** | `limited_premium_sell` * |
| VOL_EXPANSION | `atm_straddle` | `long_gamma` | — |
| VOL_COMPRESSION | `straddle_accumulate` | **`breakout_wait`** | `highly_limited_premium_sell` * |

- `*` 프리미엄 매도 계열은 `short_gamma_requires` **3개 전부**(highest_confidence + positive_gex + stable_regime) 충족해야 통과. 미충족 시 제거되고 남는 게 없으면 `short_gamma_requires_not_met`.
- `LIQUIDITY_THIN` / `CRISIS_DEFENSE`는 매트릭스에 없는 방어 전용 레짐 → 항상 빈 목록 + `defensive_regime_no_new_entries`.
- **굵게 표시한 두 칸은 진입 전략이 아니라 관망 지시다**(`NON_ENTRY_STRATEGIES`).

이어서 `enforce_daily_strategy_cap()`이 하루 상한 2개를 건다.
> **08-05 Fix#5**: 종전 구현 `(continuing + fresh)[:cap]`은 **이번 호출의 목록 길이**만 잘랐는데, 매트릭스 셀이 전부 원소 1개짜리라 `[:2]`가 자를 일이 한 번도 없었다 — 상한이 전 이력 무력이었다. 이제 `cap − len(already_used_today)`로 **남은 슬롯**만큼만 통과시킨다. 연속 사용은 상한에서 제외(새 알파 원천 추가가 아니므로).

### ⑧ 리스크 게이트 — `RiskEngine.evaluate_entry()` (`mahdi/risk/engine.py:37`)

**진입 후보가 있을 때만** 호출된다. 계좌 스냅샷이 없으면 가짜 `AccountState`를 지어내지 않고 `"account_tracker_not_ready"`로 남긴다.

평가 순서(v6 §12 독립 거부권):
1. **`market_halted`**(KRX 서킷브레이커/거래정지, `risk/market_halt.py`) → 다른 무엇도 보지 않고 **즉시 전량 거부**
2. **CircuitBreaker**(내부 킬스위치) HALTED → 거부 사유 추가
3. **한도 체계**(`check_limits`) 위반 → 사유 추가
4. **위반이 하나도 없을 때만** `compute_position_size()` 실행

| 한도 (`risk_limits.yaml`) | 값 |
|---|---|
| `per_trade_loss_pct` | −0.005 (진입 거부) |
| `daily_loss_pct` | −0.02 (신규 거래 중단) |
| `weekly_loss_pct` | −0.05 (Review 모드) |
| `max_drawdown_pct` | −0.10 (자동 정지, 수동 재가동만) |
| `max_same_direction_positions` | 3 |
| CB 트리거 | VPIN 0.90 / VIX 40 / USDKRW 일변동 2% / 데이터품질 / 모델드리프트 |

사이징 공식(v6 §12.1):
```
size = base_size × Quarter Kelly(0.25 클램프, Full Kelly 절대 금지)
     × regime_confidence × signal_quality
     × (target_vol / realized_vol)
     × liquidity_score
     × (1 − |DD| / |max_DD|)          ← 한도 도달 시 0
     × portfolio_capacity_remaining_pct
```
현재 `target_vol`/`realized_vol`/`liquidity_score`/`portfolio_capacity_remaining_pct`는 **라이브 계산처가 없어 중립값**(각각 0.01/0.01/1.0/1.0) — 알려진 한계로 문서화됨.

**거부는 항상 전량 거부** — "거부됐지만 일부 사이즈는 허용" 같은 애매한 상태를 만들지 않는다.

이 결과는 `signal_decisions.risk_gate_state` + `risk_snapshots`에 기록되고 **거기서 끝난다.** Fusion의 `decision` 자체를 바꾸지 않는다(별개 게이트).

## 5. 참고 — 이 흐름에 새겨진 설계 원칙

1. **부분 실패 허용** — 원재료 부재는 각 레이어의 `None`으로 흡수되고, 판단 자체를 죽이지 않는다.
2. **모르는 것을 지어내지 않는다** — 계좌 스냅샷 없으면 가짜 `AccountState` 대신 문자열로 사실을 남기고, 캘린더 미기입이면 페널티를 만들지 않고 경고만 낸다. `None`(못 쟀다)과 `0.0`(쟀는데 중립)은 DB에서도 구분한다.
3. **모르면 안전한 쪽** — `gamma_regime_stable`은 입력이 없으면 False(= 페널티를 거는 쪽).
4. **독립 거부권** — Risk Engine은 신호 엔진의 하위 모듈이 아니다. 어떤 신호도 거부할 수 있고, 거부는 전량 거부다.
5. **방어는 모드와 무관하게 자동** — Hard Stop / Circuit Breaker / 15:10 Forced Flat.
6. **판단 축에도 관측을 둔다** — 08-03까지 fusion·engines·risk·features·execution이 전부 무음이라 감마플립 영구 미산출이 넉 달간 안 보였다. 지금은 **판단 형태가 바뀔 때만** 한 줄 남긴다(전이 로깅).
7. **사실을 아는 쪽이 상수를 소유한다** — 구현 여부를 아는 `signal_layer.py`가 `IMPLEMENTED_MEMBER_FIELDS`를 소유하고, 세는 쪽(`db_metrics.py`)이 가져다 쓴다.
